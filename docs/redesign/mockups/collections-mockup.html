collections

One codebase, many storefronts. A collection is a filter + branding preset: it renames the app, narrows which prints are listed, and switches the submit channel and shop links. Feature flags resolve as global AND collection, so a global switch is a true kill-switch.

Collection

What the visitor lands on. In the real app this is the ?collection= parameter.

Global switches

App-wide defaults and master flags. A collection that says nothing inherits these; one that says false opts out. Nothing can turn a feature on that global has off.

Effective config

How the two levels resolve for the selected collection.

FeatureGlobal&&CollectionEffective

Where the filter gets its categories

The manifest is the index the sidebar is built from — it carries just enough to list and filter, so the app doesn't fetch every print file at startup. A print matches if it carries any of the collection's categories, and both sides are arrays — so one print can appear in several collections.


        
Each print's own prints/<id>.json also declares its categories as the source of truth — the manifest denormalizes them. Pieces, palettes and geometry load lazily when a print is selected.
